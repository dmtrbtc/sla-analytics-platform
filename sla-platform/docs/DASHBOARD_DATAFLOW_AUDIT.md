# Dashboard Data-Flow Audit

Live trace from the running stack: every dashboard tile mapped to its SQL source. Generated by exercising live endpoints with a real JWT against real production data (1,638 ticket snapshots, 30,615 events).

---

## 1. Why every tile was empty before this release

There were three independent failure modes, all proven live:

| Failure mode | Where | Symptom in UI |
|---|---|---|
| Worker dead → no metrics ever computed | `notification_tasks.py` import `requests` | All metric tiles 0 |
| Compute_sla step error-swallowed → 0 metrics for new imports | `batch_metrics_engine` had 3 chained bugs | New imports show 0 SLA |
| Metric name mismatch | Consumers queried `'response_time'`, engine emits `'first_response_time'` | Avg response time = 0 |

After fixes, the live dashboard returns:

```
$ GET /api/v1/dashboards/overview?days=30
  total_tickets: 1638
  open_tickets:  630
  closed_tickets: 1008
  sla_breach_pct: 11.68%
  avg_response_time_seconds: 7065.23        ← was 0
  avg_resolution_time_seconds: 208485.85    ← was 0
  imports_processed: 3
  tickets_by_queue: { ServiceDesk: 255, AppSupport: 150, Network: 113, ... }
```

## 3. Data-flow guardrails — preventing this from happening again

The bugs caught in this release fall into three patterns. Each pattern has a guard:

1. **Metric-name drift** (consumers query a name the engine no longer emits).
   - Guard: dashboard/report consumers accept `IN (legacy_name, current_name)`. Documented in `FORENSIC_METRICS_REFERENCE.md`.
   - Detection: `grep -rn 'metric_name == "' backend/app/` — confirm all such filters use `.in_(...)` for response-time queries.

2. **Double-prefix routes** (router mount + decorator both add the prefix).
   - Guard: there's now a one-shot grep:
     ```bash
     for f in backend/app/api/v1/*.py; do
       mod=$(basename "$f" .py)
       pref=$(grep -E "include_router\(${mod}\.router.*prefix=" backend/app/api/v1/router.py | sed -E 's/.*prefix="([^"]*)".*/\1/' | head -1)
       seg="${pref#/}"
       [ -n "$seg" ] && grep -qE "@router\.(get|post|put|delete|patch)\(\"/${seg}/" "$f" && echo "DOUBLE PREFIX: $f"
     done
     ```
   - Could be added as a pre-commit hook.

3. **Crash-handler crashes that mask real exceptions** (Celery `on_failure`).
   - Guard: always `getattr(self, '_start_time', None)`; wrap audit DB writes in try/except.
   - Pattern documented in this release's `celery_monitoring.py`.
