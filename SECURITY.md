## Сообщение об уязвимости

Если вы обнаружили уязвимость в SLA Analytics Platform:

1. **НЕ создавайте публичный issue**
2. Отправьте описание на security@example.com
3. Включите:
   - Описание уязвимости
   - Шаги воспроизведения
   - Возможное влияние
   - Предлагаемое исправление (опционально)

Мы обязуемся:
- Подтвердить получение в течение 48 часов
- Оценить критичность в течение 5 рабочих дней
- Выпустить исправление в соответствии с критичностью
- Уведомить вас о статусе исправления

## Рекомендации по безопасности

### Production развёртывание
1. **Всегда меняйте SECRET_KEY** в `.env`
2. **Не используйте --reload** в production
3. **Настройте HTTPS** через Nginx reverse proxy
4. **Регулярно обновляйте зависимости**
5. **Настройте бэкапы** PostgreSQL
6. **Ограничьте сетевой доступ** к PostgreSQL и Redis

### Аутентификация
- JWT токены с ограниченным временем жизни
- Refresh token rotation
- Password hashing через bcrypt

### База данных
- Параметры подключения только через переменные окружения
- Никаких паролей в коде
- Миграции через Alembic (без raw SQL в production)
